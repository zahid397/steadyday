# SteadyDay — demo script (about 2½ minutes)

**Set-up:** Start the app from [README](../README.md). Use a clean browser profile or delete your own disposable demo before recording. Show the app at desktop width first. Every value in the walkthrough is fictional. Do not show accounts, hosting credentials or private portal details.

| Time | Show | Narration |
| --- | --- | --- |
| 0:00–0:22 | Landing page | “SteadyDay is a wellbeing prototype for men in Bangladesh. It is designed for the moment when a busy week interrupts a routine. Instead of asking people to keep a perfect streak, it helps them see what they logged and choose one practical next step. This demo uses fictional information only.” |
| 0:22–0:48 | Choose Samir, opt in and open the prompt explanation | “Samir's example has a gap in the log. The app suggests one easy check-in and keeps the earlier entries. I can see why the suggestion appeared. Simple rules identify the context, and a small retrieval engine chooses from prewritten cards. There is no chatbot and no external AI request.” |
| 0:48–1:15 | Fill sample values, change movement to 25, save, reload and show the table | “Here is a fictional check-in: sleep, movement and self-rated energy. After I save and reload, the same numbers return from the database. I can switch the trend to movement and open its data table. A missing day stays missing; it does not count as zero.” |
| 1:15–1:40 | Set a weekly target, mark a habit, and switch to Bangla | “I can change this week’s target and mark a routine I tried. The app saves both. I can switch to Bangla from the header.” |
| 1:40–2:05 | Update energy to Very low; open qualified support; show controls | “In this fictional example, selecting very low energy replaces the movement prompt with general support information. It does not diagnose or assess urgency. I can export the practice history or delete the demo. There is no account, email or real health data in this walkthrough.” |
| 2:05–2:25 | Return to landing or show the pitch | “The prototype runs locally with Docker and PostgreSQL. A future opt-in pilot could measure whether participants understand the prompts and find them useful when resuming after a gap.” |

The live path includes the restart prompt. The accompanying narrated MP4 uses actual browser stills from the verified test run and is labeled as a walkthrough, not a continuous screen recording. Retake a continuous screen recording if the portal specifically requires one.
